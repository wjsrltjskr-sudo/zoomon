# 코드3 업무 매뉴얼 — 수정요청 처리 (주목솔라·온단)

- 작성: 총괄 3 · 2026-11-23 08:10 KST · 회장님 지시
- 이 매뉴얼은 협업_운영규칙 7절(수정요청)·8절(배포)·15절(보안)과 같이 읽는다. 다르면 규정이 맞다.

## 0. 한 줄 요약
수정요청은 총괄 3이 전담한다. 코드3은 총괄 3의 지시서만 받아 올리고, 접수·진행 답글, 완료 처리, 보고를 한다. 다른 코드·총괄은 수정요청을 만지지 않는다.

## 1. 역할
| 누구 | 하는 일 |
|---|---|
| 회장님 | 최종 승인 · 방향 |
| 총괄 3 | 수정요청 조사 · 고칠 방법 결정 · 완성 파일 · 지시서 · 라이브 확인 · 판정 |
| 코드3 | 지시서대로 서버·깃허브에 올림 · 답글 · 완료 처리 · 보고 |
| 그 밖의 총괄·코드 | 수정요청에 손대지 않음 (읽기만) |

## 2. 감시 시간
- 매일 09:00~21:00, 30분마다 (09:00, 09:30 … 21:00). 21:00 뒤·09:00 전에는 하지 않는다.
- 하나도 빠뜨리지 않는다. 회차마다 새 번호를 그 회차 안에 분류한다.
- 답글 0개 요청이 30분 넘으면 접수 답글부터 한다.

## 3. 읽기 SQL (www_zoomok · SELECT만)
```
SELECT status, count(*) FROM change_request GROUP BY status ORDER BY 1;
SELECT r.no, r.status, r.writer_name, to_char(r.created_at AT TIME ZONE 'Asia/Seoul','MM-DD HH24:MI'),
  left(coalesce(r.title, r.content),40),
  (SELECT count(*) FROM change_request_comments c WHERE c.request_no=r.no AND c.deleted_at IS NULL)
FROM change_request r
WHERE r.status NOT IN ('done','complete','completed','closed','cancel','canceled')
ORDER BY r.no DESC LIMIT 30;
```
표·칸 이름이 달라 오류가 나면 오류 글 그대로 총괄 3에게 보고(SQL 임의 수정 금지). 온단 쪽 표는 총괄 3이 따로 지시한다.

## 4. 처리 순서 (건마다)
1. 접수 답글: 「접수 · 담당 총괄3 · 처리 예정 HH:MM」
2. 총괄 3이 조사 → 완성 파일 + 지시서 (원인 → 고친 것 → 파일 sha256)
3. 코드3 반영: 옛 지문 확인 → .bak(호마다 1개) → 복사 → git push(SHA=origin) → 서버 등록 → 새 지문 일치
4. 진행·고친 내용 답글 (쉬운 말)
5. 총괄 3이 라이브 실화면(폰 폭 포함) 확인 후 PASS → 완료 처리
6. 보고

답글·완료 처리는 지시서에 적힌 번호·문구 그대로만 한다.

## 5. 금지
- 지시서 없이 코드 수정 · 지시서에 없는 파일 올리기 · --delete · 요청 글 삭제
- DB 변경(구조·데이터)은 회장님 승인 + rollback 한 쌍 없이는 금지
- 비밀번호·키·토큰·접속정보를 문서·보고·답글 어디에도 쓰지 않음
- git push만으로 「배포 끝」이라 하지 않음. 완료 기준 = 파일 지문 일치 + health 200 + 로그인 실화면
- 봉인 구역(gwmaAuth.js·봉인-음악·봉인-토의잠금) 손대지 않음
- 삭제가 필요하면 회장님께 여쭘 → 10분 답 없으면 지우지 않고 격리
- 애매한 말(아마·추정) 금지. 한 것/안 한 것을 나눠 적음
